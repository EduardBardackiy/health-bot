# Health-консультант

Telegram-бот по здоровью, тренировкам, добавкам и спортивной фармакологии.
Акцент на доказательность: ответ отделяет подтверждённые исследования от
личного опыта авторов статей и роликов.

Бота пишет и поддерживает [EduardBardackiy](https://github.com/EduardBardackiy) —
подход к фармакологии консультативный, бот не заменяет врача.

## Возможности

- **Чат** — вопросы по здоровью, тренировкам и питанию. На каждый вопрос:
  пред-поиск статей по PubMed (через Europe PMC API), топ-4 с аннотациями
  уходят модели — в ответе реальные PMID-ссылки, не выдуманные.
- **Разбор анализов** — фото бланка или PDF с результатами присылаются в чат,
  бот отвечает таблицей: показатель, значение, норма, статус.
- **Библиотека разборов** — `/report` показывает список, `/doc<N>` пришлёт
  файл. Разборы проекта (`*.md`) участвуют в ответах через мини-RAG.
- `/model` — переключение LLM-провайдера (Amvera LLM Inference / OpenAI API),
  `/clear` — сброс истории диалога.

## Архитектура

| Модуль | Что делает |
| --- | --- |
| `bot/main.py` | aiogram-бот: хендлеры, персистентная история (JSON), пин IP Telegram |
| `bot/llm.py` | LLM-провайдеры, системный промпт, разбор анализов (vision/текст), ассистент PubMed-поиска |
| `bot/rag.py` | мини-RAG: чанкинг + keyword-поиск по разборам (без эмбеддингов) |
| `bot/pmc.py` | пред-поиск статей через Europe PMC REST API (EBI-зеркало, без ключа, кэш 1 ч) |

Как работает PubMed-фид: вопрос пользователя → 3–6 английских терминов
(лёгкий вызов LLM; Medline кириллицу не находит) → запрос к Europe PMC →
топ-4 статьи `SRC:MED` в системный промпт. Результаты кэшируются на час.
Валидация PMID из ответов — отложенный второй этап (пока в этом нет нужды:
выдумывания не наблюдается).

## Запуск локально

```bash
pip install -r requirements.txt
cp .env.example .env   # заполнить BOT_TOKEN и ключ LLM-провайдера
python bot/main.py
```

Переменные окружения (см. `.env.example`):

| Переменная | Назначение |
| --- | --- |
| `BOT_TOKEN` | токен бота от @BotFather |
| `LLM_PROVIDER` | активный провайдер: `amvera` (по умолчанию) или `openai` |
| `AMVERA_API_TOKEN` | токен Amvera LLM Inference |
| `LLM_MODEL` | модель Amvera (`glm-5.1`) |
| `OPENAI_API_KEY` | ключ OpenAI API |
| `OPENAI_MODEL` | модель OpenAI (`gpt-5.5`) |
| `PROXY_URL` | прокси для Telegram, если api.telegram.org недоступен напрямую |
| `TG_PIN_IP` | пин IP `api.telegram.org` там, где DNS хромает |

## Деплой на Amvera

Приложение собирается по пушу в GitHub через вебхук (`amvera.yml` в корне).
Файлы разборов хранятся вне репозитория — на персистентном диске Амверы
(`/data`), история диалогов тоже (`/data/histories.json`), поэтому деплои
их не затирают.
